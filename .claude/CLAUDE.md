# Maven PR Review Loop

This checkout is dedicated to running an automated PR review loop for Apache Maven.
It is separate from the main development checkout.

## Purpose

Periodically review open PRs on `apache/maven` using the oss-helper `review-pr`
guideline. Track state across runs in `STATE.md`.

## Loop Configuration

- **Pattern:** PR Babysitter (review-focused)
- **Cadence:** Run via `/loop` — recommended: `/loop 1h /review-loop`
- **Level:** L2 — reviews are posted to GitHub with inline comments
- **Max PRs per run:** 3
- **Max diff size:** none (review all PRs regardless of size)

## Architecture

The loop uses a **maker/checker sub-agent pattern**:

1. **Main loop** (orchestrator) — triage is fast and inline
2. **Reviewer sub-agents** — one per PR, spawned in parallel via the Agent tool.
   Each follows the oss-helper `review-pr.md` guideline to produce structured findings.
3. **Verifier sub-agents** — one per review with findings, spawned in parallel after
   reviewers complete. Each independently re-checks findings against the diff and
   git history. Findings marked as false positives are dropped before posting.

No worktrees are used — reviews are read-only. Diffs come from `gh pr diff`.

## Safety Rules

- NEVER merge, close, or label PRs
- NEVER review draft PRs
- NEVER post unverified findings — always run the verifier sub-agent first
- ALWAYS include AI attribution in reviews
- ALWAYS update STATE.md after each review
- ALWAYS follow oss-helper review-pr.md for the actual review logic
- ALWAYS check git history before flagging issues

## Attribution

All reviews must end with:
"_This review was generated by an AI agent and may contain inaccuracies. Please verify all suggestions before applying._"

And include:
"_Claude Code on behalf of Guillaume Nodet_"

## Maven

When running Maven commands, always add `-B` (batch mode).

## State Tracking

`STATE.md` in the repo root tracks:
- Last run timestamp
- Reviewed PRs with verdicts
- Skipped PRs with reasons
- Review queue with priorities
